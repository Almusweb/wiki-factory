# TSK-002 — Estrazione repo-sync, fetta A: store applicativo, plugin store, area dati di progetto

## Context
US-013 chiede una nuova estrazione del codice di persistenza non letto, per chiudere i gap con una fonte. L'estrazione è divisa in tre fette (TSK-002, TSK-003, TSK-004) per restare nella dimensione di un documento di `repo-sync` (5-15 KB, sampling e non dump). Questa fetta copre l'ambito di US-014: percorso e comportamento su file corrotto dello store applicativo, creazione della cartella dati per progetto creato, importato o aperto da disco, tipi delle configurazioni con campi sensibili, lettore di `apiConfig` e `proxyConfig`, configurazione di ricerca e di embedding. [^src: management/kanban/EP-002-conoscenza-layer-di-persistenza/US-013-estrazione-mirata-persistenza/US-013.md §Acceptance Criteria] [^src: management/kanban/EP-002-conoscenza-layer-di-persistenza/US-014-store-applicativo-e-area-dati/US-014.md §Business Rules]

## Technical Specs
- **Consumer:** `human`, override esplicito di `routing.docs: agent` (decisione D1, confermata dall'utente il 2026-11-20). Il lavoro lo fa il ruolo Sync `repo-sync` con il comando `/repo-sync`, che non è mai automatico e ha un STOP di Fase 4 con conferma umana. Un TSK `docs` agentico si risolverebbe sul repository del cliente.
- **Target:** `llm_wiki`, **sola lettura**. Nessuna scrittura né commit nel repository del cliente (`suppress_ai_traces: true`).
- **Perimetro:** i file indicati nei gap `llm-wiki-persistenza-codice-non-letto` e `llm-wiki-app-state-percorso` / `llm-wiki-creazione-cartella-dati` pertinenti a US-014. [^src: wiki/gaps.md §2026-11-20 17:06 — llm-wiki-persistenza-codice-non-letto]
- **Output:** `raw/<data>-repo-<slug>.md` con uno slug distinto da quello della prima estrazione (per esempio `llm_wiki-persistenza-a`), perché il manifest deduplica per chiave. Voce aggiunta a `raw/.extraction-manifest.json`.
- **Nessun valore di segreto:** solo nomi e tipi di campo.

## Implementation Steps
1. Lanciare `/repo-sync` su `code_repos/llm_wiki` con l'ambito della fetta A; l'enumerazione la produce `tools/sync/repo_enumerate.py` prima dell'agente.
2. Alla Fase 4 (proposta) confermare solo l'ambito della fetta A.
3. Leggere i file dell'ambito; ogni file non letto è dichiarato non letto con motivo.
4. Dichiarare nel raw commit, ramo e numero di file letti.
5. Controllare che nel raw non compaia alcun valore di segreto e riportare l'esito del controllo.
6. Verificare a comando che il repository del cliente è invariato.

## Definition of Done
- [ ] Ogni file dell'ambito è letto o dichiarato non letto con motivo.
- [ ] Il raw dichiara commit, ramo e numero di file letti.
- [ ] Nessun valore di segreto, token o credenziale nel raw; esito del controllo riportato.
- [ ] `git -C code_repos/llm_wiki status --short` vuoto e `git -C code_repos/llm_wiki log -1 --format=%h` uguale a quello iniziale (comandi ed esiti riportati).
- [ ] Voce nel manifest aggiunta senza sovrascrivere voci altrui.
