# TSK-004 — Estrazione repo-sync, fetta C: operazioni distruttive, chiamanti, vecchio formato vettoriale

## Context
Terza e ultima fetta dell'estrazione di US-013. Copre l'ambito di US-016: cascata di cancellazione di una pagina, ciclo di vita delle sorgenti, pulizia delle review, cancellazione dei file di chat, chiamanti dell'accodamento di turno di sessione agente con i relativi identificativi, endpoint che scrivono, cancellazioni nella scrittura generica di file, e chiamanti di scrittura e cancellazione del vecchio formato vettoriale. Chiude anche il conteggio cumulativo dei file letti richiesto da US-013. [^src: management/kanban/EP-002-conoscenza-layer-di-persistenza/US-016-chiamanti-operazioni-distruttive/US-016.md §Business Rules] [^src: management/kanban/EP-002-conoscenza-layer-di-persistenza/US-013-estrazione-mirata-persistenza/US-013.md §Acceptance Criteria]

## Technical Specs
- **Consumer:** `human`, override esplicito di `routing.docs: agent` (decisione D1, confermata dall'utente il 2026-11-20). Ruolo Sync `repo-sync` con `/repo-sync` e STOP di Fase 4. Un TSK `docs` agentico si risolverebbe sul repository del cliente.
- **Target:** `llm_wiki`, **sola lettura**; nessun commit nel repository del cliente.
- **Perimetro:** file dei gap `llm-wiki-persistenza-codice-non-letto` e `llm-wiki-vector-v1-chiamanti` pertinenti a US-016. Un chiamante non trovato è dichiarato assente con l'ambito cercato. [^src: wiki/gaps.md §2026-11-20 17:06 — llm-wiki-vector-v1-chiamanti]
- **Output:** `raw/<data>-repo-<slug>.md` (slug distinto, per esempio `llm_wiki-persistenza-c`) e voce nel manifest. Nel raw o nella voce di manifest, il numero cumulativo di file letti sulle tre fette e l'elenco dei punti del gap `llm-wiki-persistenza-codice-non-letto` ancora scoperti.

## Implementation Steps
1. Lanciare `/repo-sync` su `code_repos/llm_wiki` con l'ambito della fetta C, dopo la chiusura di TSK-003.
2. Alla Fase 4 confermare solo l'ambito della fetta C.
3. Per ogni operazione distruttiva riportare i chiamanti con riferimento, o «nessun chiamante nell'ambito cercato».
4. Riportare l'identificativo di sessione usato dai chiamanti dell'accodamento di turno.
5. Dichiarare commit, ramo, numero di file letti in questa fetta e cumulativo sulle tre.
6. Controllare l'assenza di segreti e la non modifica del repository del cliente.
