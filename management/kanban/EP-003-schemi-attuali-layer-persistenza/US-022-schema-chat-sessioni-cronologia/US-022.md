# US-022 — Documentare lo schema di chat, sessioni agente e cronologia file

## Descrizione
Come sviluppatore del layer di persistenza, voglio lo schema documentato di chat (indice e file per conversazione), sessioni agente e cronologia dei file, con limiti di conservazione e indirizzamento, affinché io conosca cosa viene conservato, cosa viene troncato e come si trovano i file.

## Business Rules
- Chat: indice delle conversazioni più un file per conversazione; immagini e contenuti prima e dopo le modifiche dell'agente non sono persistiti; si salvano gli ultimi 100 messaggi per conversazione.
- Sessioni agente: un file per sessione, solo gli ultimi 40 messaggi, identificativo sanitizzato, valori di default per i file vecchi.
- Cronologia: un file per percorso relativo, indirizzato da un hash FNV-1a a 64 bit con costanti fisse sul percorso relativo; voci fino a 512 KB; potatura oltre 128 MiB o 2.048 file; impostazioni con massimo 30 versioni per file e default disattivata.

## Acceptance Criteria
- [ ] Sono documentati i campi di conversazione e messaggio di chat, con quali sono opzionali e quali non sono persistiti.
- [ ] Sono documentati i campi della sessione agente e della voce di cronologia, con i valori di default dichiarati.
- [ ] Sono documentati i limiti di conservazione (100, 40, 512 KB, 30 versioni, 128 MiB, 2.048 file) con la regola di troncamento o potatura di ciascuno.
- [ ] Il nome del file di cronologia è documentato con rimando alla derivazione nell'indice di `design_&_architecture/db_schemas/` (identificatore I7: hash FNV-1a a 64 bit con costanti fisse sul percorso relativo); la scheda non ripete la derivazione. Il nome della revisione di embedding non è un hash del percorso (`sha256(page_id)`, identificatore I6 dell'indice) ed è trattato in US-020. [^src: wiki/concepts/llm-wiki-archivi-persistenza.md §Inventario]
- [ ] I punti che dipendono da codice non letto (chiamanti dell'accodamento di turno) sono marcati «non verificato» con rimando al gap.
