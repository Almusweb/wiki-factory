# US-021 — Documentare lo schema degli archivi per progetto

## Descrizione
Come sviluppatore del layer di persistenza, voglio lo schema documentato degli archivi di dati di progetto (identità, coda di ingest, cache di ingest, review, lint e relativa configurazione, impostazioni di chat, elenco «non duplicati», database di import schedulato, impostazioni della cronologia), affinché io conosca campi, valori ammessi e comportamento su file illeggibile.

## Business Rules
- Per ogni archivio: campi, opzionalità, valori ammessi (per esempio gli stati dei task e i tipi di review), versione dichiarata e comportamento quando il file manca o è illeggibile.
- Versioni: solo il database di import schedulato dichiara `version: 1`; per gli altri la versione è «nessuna».
- I task completati della coda di ingest non vengono salvati.
- Il tipo degli elementi di lint non è noto finché non letto: va marcato «non verificato» con rimando ai gap.

## Acceptance Criteria
- [ ] Ogni archivio per progetto elencato sopra ha una scheda con posizione, campi, opzionalità, valori ammessi e versione.
- [ ] Ogni scheda riporta il comportamento su file mancante o illeggibile e l'effetto della scrittura successiva, come in wiki.
- [ ] Il tipo degli elementi di lint è marcato «non verificato» con rimando al gap `llm-wiki-persistenza-codice-non-letto`.
- [ ] Per l'archivio dell'identità del progetto è documentato che un file mancante o corrotto genera un nuovo identificativo.
- [ ] Nessun campo è aggiunto che non sia nella wiki.
