# TSK-022 — Dossier EP-004, rischio 4: lettura dell'atomicità di scrittura per archivio

## Context
US-028 chiede, archivio per archivio, se la scrittura è diretta o con file temporaneo e rinomina, cosa fa il caricamento davanti a un file troncato o vuoto, e il passaggio non atomico su Windows nella ricostruzione dell'indice. Sola lettura (Q_003), esito nel dossier di EP-004 scritto da `repo-sync` (Q_005). La fetta D (`raw/2026-11-21-repo-llm_wiki-persistenza-d.md`, ingerita) copre già l'atomicità per archivio: il dossier parte da lì, conferma o corregge, non ripete. ## Technical Specs
- **Consumer:** `human`, override esplicito di `routing.docs: agent` (D1); lavoro di `repo-sync`, STOP di Fase 4.
- **Prerequisiti dichiarati: TSK-011** (sorgente leggibile, submodule `code_repos/llm_wiki` al commit `e08cfce`) e **TSK-020** (serializzazione sul manifest).
- **Punto di partenza:** tabella di atomicità per archivio già in wiki (fetta D, US-015) e comportamento dei file corrotti (US-021). Il dossier riporta solo conferme, correzioni e lacune residue, con file, simboli e righe.
- **Limite dichiarato in anticipo:** garanzie del file system e della libreria di scrittura non osservabili per lettura: «non conclusivo» con motivo. Nessuna interruzione simulata, nessuna esecuzione.
- **Target:** `llm_wiki`, sola lettura.
- **Output:** `raw/<data>-repo-llm_wiki-dossier-ep004-r4.md`, voce `source: repo` nel manifest; seriale dopo TSK-020.
- **Perimetro di lettura:** scrittura di sessioni agente e cronologia (diretta) e relativo caricamento con file troncato o vuoto; configurazione di lint, database di import schedulato, revisioni di embedding (temporaneo e rinomina); passaggio di eliminazione dell'originale prima della rinomina su Windows in `embedAllPages`/ricostruzione dell'indice e cosa legge un lettore concorrente; archivi che dipendono dalla scrittura generica di file, se non già chiusi dalla fetta D.
- Nessun valore di segreto.

## Implementation Steps
1. Verificare TSK-011 e TSK-020 chiusi; rileggere le sezioni fetta D citate per non ripetere.
2. Lanciare `/repo-sync` con il solo perimetro; alla Fase 4 confermare solo questo ambito.
3. Per ogni archivio: confermare o correggere la modalità di scrittura (diretta o temporaneo e rinomina).
4. Per gli archivi a scrittura diretta: riportare il comportamento del caricamento con file troncato o vuoto, con rimando a US-021.
5. Riportare la finestra non atomica su Windows e cosa legge un lettore concorrente.
6. Esito per archivio (confermato/smentito/non conclusivo) con impatto sui dati; commit, ramo, file letti e non letti, controllo segreti, repo cliente invariato.
