# TSK-012 — Dossier EP-004, rischio 1: lettura del percorso cancella-salva-carica delle chat

## Context
US-025 chiede se le chat cancellate possono ricomparire, per sola lettura del codice (Q_003), con file e simboli letti, e vuole l'esito nel dossier di EP-004 scritto da `repo-sync` (Q_005). Le fette ingerite hanno già trovato la rimozione fisica nel cestino di `ConversationSidebar` (`chat-panel.tsx:235-265`, senza attesa, errore ignorato), ma restano deduzioni lette da estrazioni «solo mappa»: qui si rilegge il sorgente per tracciare il percorso intero. [^src: management/kanban/EP-004-verifica-rischi-di-persistenza/US-025-rischio-chat-cancellate/US-025.md §Acceptance Criteria] [^src: wiki/concepts/llm-wiki-rischi-persistenza.md §Dettaglio]

## Technical Specs
- **Consumer:** `human`, override esplicito di `routing.docs: agent` (decisione D1). Il lavoro lo fa `repo-sync` con `/repo-sync`, mai automatico, con STOP di Fase 4 e conferma umana. Un TSK `docs` agentico si risolverebbe sul repository del cliente.
- **Prerequisito dichiarato: TSK-011** (submodule inizializzato a `e08cfce`). L'AC «per sola lettura del codice, con file e simboli letti» **non è soddisfacibile dalla wiki**: richiede il sorgente, che oggi non è estratto né presente. Senza TSK-011 questo TSK resta bloccato; non si ricopia dai raw già ingeriti.
- **Target:** `llm_wiki`, sola lettura. Nessuna esecuzione dell'applicazione, nessuna modifica al repository del cliente.
- **Output:** `raw/<data>-repo-llm_wiki-dossier-ep004-r1.md` (slug distinto: l'epica ammette più dossier; il manifest deduplica per chiave) con voce `source: repo` in `raw/.extraction-manifest.json`, aggiunta senza sovrascrivere voci altrui. Serie di EP-004: r1 (questo), r2, r3, r5, r6; r4, r7, r8 verranno con le storie ancora bloccate.
- **Perimetro di lettura:** `deleteConversation` in `src/stores/chat-store.ts`; `saveChatHistory` e `loadChatHistory` in `src/lib/persist.ts`; il gestore del cestino di `ConversationSidebar` (`chat-panel.tsx`, righe 235-265); il percorso «cancella tutte le conversazioni» (store, salvataggio, indice delle chat, ricostruzione da `chats/*.json` con indice vuoto); i chiamanti di `loadChatHistory` e `saveChatHistory` (momento di salvataggio, debounce). Riserva ereditata da TSK-008: la stringa `agent-sessions/` non è stata cercata, se rilevante per le cancellazioni va dichiarata letta o non letta.
- **Per ogni conclusione:** file, simbolo, righe. Esito proposto: confermato, smentito o non conclusivo, con il motivo del «non conclusivo» (es. fallimento silenzioso della cancellazione su file bloccato, non osservabile per lettura).
- **Nessun valore di segreto:** solo nomi e tipi.

## Implementation Steps
1. Verificare TSK-011 chiuso (`git -C code_repos/llm_wiki log -1 --format=%h` → `e08cfce`).
2. Lanciare `/repo-sync` su `code_repos/llm_wiki` con il solo perimetro sopra; alla Fase 4 confermare solo questo ambito.
3. Leggere i file e tracciare: cancellazione di tutte le conversazioni, successivo salvataggio, successivo caricamento, lettura dei file orfani con indice vuoto.
4. Riportare dove e con quale innesco i file `chats/<id>.json` sono cancellati fisicamente (da TSK-008) o che non esiste altra cancellazione nel codice letto.
5. Dichiarare l'esito proposto e, se confermato, l'impatto (perdita o divergenza).
6. Dichiarare commit, ramo, file letti e non letti con motivo; controllo segreti; confermare a comando che il repo cliente è invariato.
