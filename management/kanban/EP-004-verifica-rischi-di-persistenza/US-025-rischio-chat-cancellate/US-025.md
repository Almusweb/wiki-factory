# US-025 — Verificare il rischio 1 (chat cancellate che ricompaiono)

## Descrizione
Come maintainer del layer di persistenza, voglio sapere se le conversazioni cancellate dall'utente possono ricomparire al caricamento successivo, affinché si decida se serve una correzione sapendo se l'effetto esiste davvero.

## Business Rules
- Stato di partenza: deduzione, **non verificato**. La cancellazione rimuove la conversazione dallo store ma il salvataggio non elimina i file di conversazione orfani; il caricamento ricostruisce l'indice da quei file quando l'indice è vuoto.
- La rimozione fisica dei file potrebbe stare in codice non letto: questo punto lo chiude US-016.
- Metodo ammesso: **sola lettura del codice** (Q_003). Nessuna esecuzione dell'applicazione, nessun test di caratterizzazione, nessuna modifica al repository del cliente.
- Si verifica l'effetto; la correzione è fuori scope.

## Acceptance Criteria
- [ ] L'esito parte dall'ipotesi come in wiki e si ottiene per sola lettura del codice; per ogni conclusione sono riportati i file e i simboli letti.
- [ ] È riportato, per lettura, dove e con quale innesco i file di conversazione vengono cancellati fisicamente (da US-016), oppure che nel codice letto non esiste una cancellazione.
- [ ] Sono tracciati per lettura il percorso di cancellazione di tutte le conversazioni, il successivo salvataggio e il successivo caricamento, indicando se i file orfani vengono letti per ricostruire l'indice.
- [ ] L'esito è dichiarato confermato, smentito o non conclusivo per lettura; se confermato, è indicato l'impatto sui dati (perdita o divergenza).
- [ ] Dove la sola lettura non basta (per esempio cancellazione in codice non letto), l'esito è «non conclusivo» e il motivo è dichiarato.
- [ ] Nessuna esecuzione dell'applicazione e nessuna modifica al repository del cliente.
- [ ] L'esito è scritto come raw in `raw/` da un ruolo Sync dedicato (da definire, Q_005), senza Bash e per sola lettura del codice, ed è poi ingerito da `wiki-keeper`; non è scritto direttamente in `wiki/`.
