# TSK-014 — Dossier EP-004, rischio 2: lettura della rigenerazione dell'identità del progetto

## Context
US-026 chiede cosa accade se `project.json` è corrotto: nuovo identificativo, task scartati come «cross-project» alla ripartenza della coda, impostazioni per progetto dello store rimaste orfane. Tutto per sola lettura del codice (Q_003), con file e simboli, nel dossier di EP-004 scritto da `repo-sync` (Q_005). [^src: management/kanban/EP-004-verifica-rischi-di-persistenza/US-026-rischio-identita-progetto/US-026.md §Acceptance Criteria] [^src: wiki/concepts/llm-wiki-rischi-persistenza.md §Dettaglio]

## Technical Specs
- **Consumer:** `human`, override esplicito di `routing.docs: agent` (D1); lavoro di `repo-sync` via `/repo-sync`, con STOP di Fase 4.
- **Prerequisito dichiarato: TSK-011.** Gli AC richiedono lettura del sorgente non estratto (le fette ingerite sono «solo mappa» su molti punti): senza submodule il TSK non parte. Se la lettura non basta (es. punto non raggiungibile), l'esito è «non conclusivo» con motivo.
- **Target:** `llm_wiki`, sola lettura. Nessuna esecuzione, nessun file corrotto simulato.
- **Output:** `raw/<data>-repo-llm_wiki-dossier-ep004-r2.md`, voce `source: repo` nel manifest. Seriale dopo TSK-012 (stesso manifest).
- **Perimetro di lettura:** `ensureProjectId` e `upsertProjectInfo` in `project-identity.ts` (generazione UUID, scrittura, eventuale conservazione del vecchio id; l'id è assegnato dal frontend, non dal backend); `restoreQueue` in `ingest-queue.ts` (scarto dei task con id diverso); i tipi in `wiki-store.ts` e i punti di scrittura di `projectLlmOverrides`, `projectOutputLanguages`, `sourceWatchConfig`, `projectFileSyncEnabled`; ricerca di un punto che li riallinei al nuovo id. Il lato Rust (`create_project`, `open_project`, `import_project_archive`) solo per confermare che non assegna l'id.
- Collegamento con rischio 3: la collisione di id dopo l'import (gap `llm-wiki-import-id-duplicato`) è un'ipotesi non verificata; se letta, si riporta separatamente, senza allargare l'esito del rischio 2.
- Nessun valore di segreto.

## Implementation Steps
1. Verificare TSK-011 e TSK-012 chiusi (commit `e08cfce`, manifest aggiornato dal dossier r1).
2. Lanciare `/repo-sync` con il solo perimetro; alla Fase 4 confermare solo questo ambito.
3. Tracciare «file di identità illeggibile»: nuovo id, scrittura, destino del vecchio id.
4. Riportare l'effetto della ripartenza della coda sui task con vecchio id.
5. Elencare le impostazioni indicizzate per id e se un punto le riallinea.
6. Esito proposto con impatto; commit, ramo, file letti e non letti, controllo segreti, repo cliente invariato.
