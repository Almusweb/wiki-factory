# US-003 — Analizzare e segnalare il difetto 3 (hook di messaggio di commit e ID senza prefisso)

## Descrizione
Come maintainer della factory, voglio sapere se l'hook di messaggio di commit installato nei submodule con politica anti-traccia AI lascia passare ID kanban privi di prefisso di namespace, affinché un ID della factory non finisca in un commit del cliente e il master riceva una segnalazione riproducibile.

## Business Rules
- Stato di partenza: osservato in sessione. Un messaggio con un ID senza prefisso passa (exit 0), mentre lo strumento di policy della factory lo rileva; l'attribuzione AI esplicita è bloccata correttamente (exit 1).
- Il prefisso di namespace è opzionale nello strumento di policy della factory ma non nell'hook.
- La riproduzione non crea commit nel repository del cliente.

## Acceptance Criteria
- [ ] L'hook è provato su un repository di prova neutro, senza creare commit nel repository del cliente, con: ID con prefisso, ID senza prefisso, attribuzione AI esplicita; per ogni caso sono riportati messaggio, exit code ed esito.
- [ ] Lo stesso insieme di messaggi è confrontato con il rilevamento di ID dello strumento di policy della factory.
- [ ] È riportata la differenza fra le due espressioni di riconoscimento degli ID.
- [ ] L'esito è dichiarato confermato, smentito o non conclusivo, con la versione del master verificata.
- [ ] Il report è un documento in `deliverables/`, nel modello di US-012, riprodotto su un caso neutro (repository e factory neutri, ID di esempio) e privo di ogni dettaglio escluso da Q_002 (nome o URL del repository di codice, percorsi della factory e del repository di codice, hash, nomi utente, nome di questa factory; sono ammessi i percorsi dei file del master oggetto del difetto).
- [ ] La segnalazione al master non fa parte della storia: la fa l'utente con il canale che preferisce, partendo dal report.
